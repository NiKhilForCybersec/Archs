Security Baselines

Security baselines define the minimum security configuration standards for systems, applications, and infrastructure. They reduce attack surface, ensure consistency, and provide a foundation for compliance.

CIS Benchmarks

Center for Internet Security (CIS) Benchmarks

CIS Benchmarks are consensus-based security configuration guides developed by security experts worldwide. They provide step-by-step hardening recommendations for operating systems, applications, cloud platforms, and network devices.

Level 1: Basic security settings, minimal impact on functionality. Recommended for all systems.

Level 2: Defense-in-depth settings, may impact functionality. For high-security environments.

Windows Server Hardening

Key Windows Security Settings
# Windows Server 2022 - Critical Baseline Settings

# 1. ACCOUNT POLICIES
# ───────────────────
# Password Policy (via GPO or Local Security Policy)
Minimum password length: 14 characters
Password complexity: Enabled
Account lockout threshold: 5 invalid attempts
Account lockout duration: 30 minutes

# 2. AUDIT POLICIES
# ─────────────────
# Enable critical audit events
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Account Lockout" /failure:enable
auditpol /set /subcategory:"Sensitive Privilege Use" /success:enable
auditpol /set /subcategory:"Process Creation" /success:enable

# 3. DISABLE UNNECESSARY SERVICES
# ───────────────────────────────
Set-Service -Name "RemoteRegistry" -StartupType Disabled
Set-Service -Name "SNMP" -StartupType Disabled
Set-Service -Name "Telnet" -StartupType Disabled

# 4. WINDOWS FIREWALL
# ──────────────────
Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True
Set-NetFirewallProfile -DefaultInboundAction Block
Set-NetFirewallProfile -DefaultOutboundAction Allow

# 5. SMB HARDENING
# ───────────────
Set-SmbServerConfiguration -EnableSMB1Protocol $false  # Critical!
Set-SmbServerConfiguration -RequireSecuritySignature $true

# 6. LSASS PROTECTION
# ──────────────────
# Enable Credential Guard (requires hardware support)
# Registry: HKLM\SYSTEM\CurrentControlSet\Control\LSA
# LsaCfgFlags = 1 (with UEFI lock)

Linux Hardening

Key Linux Security Settings
# Ubuntu/RHEL - Critical Baseline Settings

# 1. SSH HARDENING (/etc/ssh/sshd_config)
# ───────────────────────────────────────
PermitRootLogin no
PasswordAuthentication no  # Use keys only
MaxAuthTries 3
ClientAliveInterval 300
ClientAliveCountMax 2
AllowUsers admin deploy    # Explicit allow list
Protocol 2

# 2. FILESYSTEM SECURITY
# ─────────────────────
# Restrict /tmp, /var/tmp
# /etc/fstab entries:
tmpfs /tmp tmpfs defaults,noexec,nosuid,nodev 0 0

# Set permissions on sensitive files
chmod 600 /etc/shadow
chmod 644 /etc/passwd
chmod 700 /root

# 3. KERNEL HARDENING (/etc/sysctl.conf)
# ─────────────────────────────────────
net.ipv4.ip_forward = 0
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
kernel.randomize_va_space = 2  # ASLR
fs.suid_dumpable = 0

# 4. FIREWALL (UFW/firewalld)
# ─────────────────────────
ufw default deny incoming
ufw default allow outgoing
ufw allow ssh
ufw enable

# 5. REMOVE UNNECESSARY PACKAGES
# ─────────────────────────────
apt remove telnetd rsh-server xinetd  # Ubuntu
yum remove telnet-server rsh-server   # RHEL

Baseline Best Practices

Security Baseline Guidelines

1. Start with Standards: Don't reinvent. Use CIS Benchmarks, DISA STIGs as your foundation.

2. Test Before Deploying: Baselines can break applications. Lab testing is essential.

3. Automate Enforcement: GPO for Windows, Ansible/Chef/Puppet for Linux. Manual hardening doesn't scale.

4. Continuous Monitoring: Configuration drift happens. Scan regularly, alert on deviations.

5. Document Exceptions: Not all settings work for all systems. Track approved exceptions.

6. Golden Images: Bake baselines into VM templates. New systems start compliant.
