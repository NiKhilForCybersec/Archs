GCP Security

Google Cloud Platform security leverages Google's infrastructure and security expertise. GCP's resource hierarchy, IAM model, and Security Command Center provide powerful tools for securing cloud workloads.

GCP Resource Hierarchy

GCP Organization Structure
# GCP Resource Hierarchy (IAM policies inherit downward)

Organization (company.com)
├── Folder: Production
│   ├── Project: prod-app-frontend
│   │   ├── Compute Engine instances
│   │   ├── Cloud Storage buckets
│   │   └── Cloud SQL databases
│   └── Project: prod-app-backend
│       ├── GKE clusters
│       └── Pub/Sub topics
├── Folder: Development
│   ├── Project: dev-sandbox
│   └── Project: dev-staging
├── Folder: Shared Services
│   ├── Project: shared-networking (VPC, DNS)
│   ├── Project: shared-logging (Log sinks)
│   └── Project: shared-security (SCC, KMS)
└── Folder: Data
    ├── Project: data-warehouse (BigQuery)
    └── Project: data-lake (Cloud Storage)

Key Concepts:
  • Organization: Root node, tied to Cloud Identity domain
  • Folders: Group projects, apply policies at scale
  • Projects: Container for resources, billing boundary
  • IAM inheritance: Org → Folder → Project → Resource

IAM Best Practices
# Grant roles at appropriate level
gcloud projects add-iam-policy-binding prod-app \
  --member="group:[email protected]" \
  --role="roles/viewer"

# Use custom roles for least privilege
gcloud iam roles create customAppRole \
  --project=prod-app \
  --permissions=storage.objects.get,storage.objects.list

# Prefer Workload Identity over service account keys
# Service account keys are security risks - they don't expire!

# Use IAM Conditions for context-aware access
gcloud projects add-iam-policy-binding prod-app \
  --member="user:[email protected]" \
  --role="roles/compute.viewer" \
  --condition="expression=request.time < timestamp('2024-12-31T00:00:00Z'),title=temp-access"

Security Command Center

Security Health Analytics

Misconfiguration detection. Public buckets, firewall issues, encryption gaps. Auto-scans GCP resources.

Event Threat Detection

Threat detection from logs. Cryptocurrency mining, malware, data exfiltration patterns.

Container Threat Detection

GKE runtime security. Suspicious binaries, reverse shells, privilege escalation in containers.

Web Security Scanner

DAST for App Engine, GKE, Compute Engine. XSS, SQLi, outdated libraries.

VPC Security

VPC Firewall Rules
# GCP Firewall Rules (stateful, priority-based)

# Deny all ingress by default (implicit)
# Allow specific traffic explicitly

# Allow internal communication
gcloud compute firewall-rules create allow-internal \
  --network=prod-vpc \
  --allow=tcp,udp,icmp \
  --source-ranges=10.0.0.0/8 \
  --priority=1000

# Allow HTTPS from internet to tagged instances
gcloud compute firewall-rules create allow-https \
  --network=prod-vpc \
  --allow=tcp:443 \
  --source-ranges=0.0.0.0/0 \
  --target-tags=web-server \
  --priority=1000

# Deny egress to known bad IPs (example)
gcloud compute firewall-rules create deny-bad-egress \
  --network=prod-vpc \
  --direction=EGRESS \
  --action=DENY \
  --rules=all \
  --destination-ranges=198.51.100.0/24 \
  --priority=100

GCP Security Best Practices

GCP Security Implementation Guidelines

1. Use Organization & Folders: Structure hierarchy for policy inheritance. Org policies at top, exceptions at project level.

2. Avoid Service Account Keys: Use Workload Identity for GKE. Use attached service accounts for Compute. Keys are security debt.

3. Enable Security Command Center: Premium tier for threat detection. Integrate findings with SIEM.

4. VPC Service Controls: Create perimeters around sensitive projects. Prevent data exfiltration to unauthorized projects.

5. Enable Audit Logs: Admin Activity (default), Data Access (enable for sensitive resources). Export to BigQuery/SIEM.

6. Use Cloud KMS: Customer-managed encryption keys (CMEK) for sensitive data. Key rotation, access controls.
