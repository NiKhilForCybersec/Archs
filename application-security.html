Application Security

Application Security (AppSec) ensures software is designed, developed, and deployed securely. Through SAST, DAST, SCA, and secure coding practices, AppSec prevents vulnerabilities from reaching production.

OWASP Top 10 (2021)

OWASP Top 10 Web Application Risks
# OWASP Top 10 - 2021

A01: BROKEN ACCESS CONTROL
     Users acting outside their intended permissions
     → Enforce least privilege, deny by default

A02: CRYPTOGRAPHIC FAILURES
     Weak encryption, plaintext data, missing TLS
     → Encrypt sensitive data, strong algorithms

A03: INJECTION
     SQL, NoSQL, OS command, LDAP injection
     → Parameterized queries, input validation

A04: INSECURE DESIGN
     Missing security controls, threat modeling gaps
     → Secure design patterns, threat modeling

A05: SECURITY MISCONFIGURATION
     Default configs, unnecessary features enabled
     → Hardening, remove defaults, automate config

A06: VULNERABLE COMPONENTS
     Using components with known vulnerabilities
     → SCA scanning, patch management, SBOM

A07: IDENTIFICATION AND AUTHENTICATION FAILURES
     Weak passwords, missing MFA, session issues
     → Strong auth, MFA, secure session management

A08: SOFTWARE AND DATA INTEGRITY FAILURES
     CI/CD pipeline compromises, insecure deserialization
     → Code signing, integrity verification

A09: SECURITY LOGGING AND MONITORING FAILURES
     Insufficient logging, no alerting
     → Comprehensive logging, SIEM integration

A10: SERVER-SIDE REQUEST FORGERY (SSRF)
     Application fetches remote resources without validation
     → Allowlist URLs, sanitize input

Security in CI/CD

Security Gates in Pipeline
# GitLab CI Security Pipeline Example

stages:
  - build
  - security
  - test
  - deploy

# Static Analysis (SAST)
sast:
  stage: security
  script:
    - semgrep --config=auto --json > sast-results.json
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  allow_failure: false  # Block on high severity

# Dependency Scanning (SCA)
dependency_scan:
  stage: security
  script:
    - snyk test --severity-threshold=high
  allow_failure: false  # Block on high/critical CVEs

# Secret Scanning
secret_scan:
  stage: security
  script:
    - gitleaks detect --source . --verbose
  allow_failure: false  # Always block on secrets

# Container Scanning
container_scan:
  stage: security
  script:
    - trivy image --severity HIGH,CRITICAL myapp:$CI_COMMIT_SHA
  allow_failure: false

# DAST (against staging)
dast:
  stage: test
  script:
    - zap-baseline.py -t https://staging.company.com
  allow_failure: true  # Alert but don't block (review findings)

AppSec Best Practices

Application Security Guidelines

1. Shift Left: Security testing in IDE and CI, not just before release. Earlier = cheaper to fix.

2. Automate Everything: Manual security reviews don't scale. Automate SAST, SCA, secret scanning.

3. Developer-Friendly: Integrate with developer tools (IDE, PR comments). Reduce friction.

4. Prioritize Ruthlessly: Not all findings are equal. Focus on exploitable, high-risk issues.

5. Secure Defaults: Frameworks should be secure by default. Make insecure hard.

6. Security Champions: Embed security-minded developers in each team.
