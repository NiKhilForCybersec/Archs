SIEM Architecture

Security Information and Event Management (SIEM) systems aggregate logs from across the enterprise, correlate events, detect threats, and support incident investigation. Modern SIEM platforms combine traditional log management with advanced analytics, UEBA, and SOAR capabilities.

SIEM Functions

A SIEM platform performs several critical security functions:

Log Aggregation

Centralized collection of security logs from firewalls, endpoints, servers, applications, cloud services, and identity systems.

Normalization

Converting diverse log formats into a common schema for consistent querying and correlation across sources.

Correlation

Connecting related events across systems to identify attack patterns that wouldn't be visible in isolated logs.

Alerting

Real-time detection rules that trigger alerts when suspicious activity matches defined patterns or thresholds.

Investigation

Search and analysis tools for threat hunting and incident investigation with full historical context.

Compliance

Retention policies, audit trails, and reporting to meet regulatory requirements (PCI-DSS, HIPAA, SOX).

Traditional vs. Modern SIEM

Traditional SIEM (Legacy)
  • On-premises appliances
  • License by EPS (events per second)
  • Manual rule writing (regex-heavy)
  • Limited cloud visibility
  • High false positive rates
  • Separate tools for each function
  • Complex scaling
  • 90-day retention typical
Modern SIEM (Cloud-Native)
  • Cloud-native architecture
  • License by data ingestion (GB/day)
  • Built-in detection content (MITRE-mapped)
  • Native cloud & SaaS connectors
  • ML-based anomaly detection
  • Integrated UEBA & SOAR
  • Elastic auto-scaling
  • 1-7 year retention standard

Detection Rule Example: Brute Force Attack

Microsoft Sentinel KQL Detection
KQL - Failed Logon Brute Force Detection 
// Detect brute force attacks: 10+ failed logins followed by success
let threshold = 10;
let timeWindow = 1h;

SecurityEvent
| where EventID == 4625  // Failed logon
| summarize 
    FailedAttempts = count(),
    FirstFailure = min(TimeGenerated),
    LastFailure = max(TimeGenerated),
    TargetAccounts = make_set(TargetUserName)
    by SourceIP = IpAddress, TargetComputer = Computer
| where FailedAttempts >= threshold
| join kind=inner (
    SecurityEvent
    | where EventID == 4624  // Successful logon
    | where TimeGenerated > ago(timeWindow)
    | project SuccessTime = TimeGenerated, SourceIP = IpAddress, 
              SuccessAccount = TargetUserName, TargetComputer = Computer
) on SourceIP, TargetComputer
| where SuccessTime > LastFailure
| extend TimeDelta = datetime_diff('minute', SuccessTime, LastFailure)
| where TimeDelta <= 30  // Success within 30 min of last failure
| project 
    SourceIP,
    TargetComputer,
    FailedAttempts,
    SuccessAccount,
    FirstFailure,
    LastFailure,
    SuccessTime,
    TimeDelta,
    TargetAccounts

SIEM Best Practices

Implementation Success Factors

1. Define Use Cases First: Don't collect logs just because you can. Define detection use cases, then determine required data sources.

2. Normalize Early: Invest in proper parsing and field extraction upfront. Inconsistent data makes correlation impossible.

3. Tune Aggressively: A SIEM generating 1000 alerts/day with 90% false positives is worse than useless. Quality over quantity.

4. Map to MITRE ATT&CK: Ensure detection coverage across the attack lifecycle. Identify and fill gaps systematically.

5. Automate Response: Integrate with SOAR for automated enrichment and response. Reduce analyst fatigue.

6. Measure Effectiveness: Track MTTD (Mean Time to Detect) and MTTR (Mean Time to Respond). Continuously improve.
