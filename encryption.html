Encryption

Encryption transforms readable data into unreadable ciphertext, protecting confidentiality at rest, in transit, and in use. Understanding encryption types, algorithms, and implementation is fundamental to data protection.

Encryption Types

Symmetric Encryption
  • Same key encrypts and decrypts
  • Fast, efficient for large data
  • Challenge: Secure key distribution
  • Algorithms: AES-256, ChaCha20
  • Use: Data at rest, bulk encryption
Plaintext + Key → Ciphertext
Ciphertext + Same Key → Plaintext

Key size: 128, 192, or 256 bits
Speed: ~1 GB/sec on modern CPUs
Asymmetric Encryption
  • Public key encrypts, private key decrypts
  • Slower, used for small data/key exchange
  • Solves key distribution problem
  • Algorithms: RSA-2048+, ECDSA, Ed25519
  • Use: TLS handshake, digital signatures
Plaintext + Public Key → Ciphertext
Ciphertext + Private Key → Plaintext

RSA key: 2048-4096 bits
Speed: ~1000x slower than symmetric

TLS Encryption (In Transit)

TLS 1.3 Handshake
1
Client Hello
Client initiates connection
Client → Server
ClientHello:
  - TLS Version: 1.3
  - Supported Cipher Suites:
    - TLS_AES_256_GCM_SHA384
    - TLS_CHACHA20_POLY1305_SHA256
  - Key Share: ECDHE public key (Curve25519)
  - SNI: api.company.com
2
Server Hello + Certificate
Server responds with certificate and key share
Server → Client
ServerHello:
  - Selected Cipher: TLS_AES_256_GCM_SHA384
  - Key Share: Server ECDHE public key
  
Certificate:
  - Server certificate (signed by CA)
  - Certificate chain to root CA
  
CertificateVerify:
  - Signature proving server owns private key
3
Encrypted Communication
Both sides derive session keys
Session Established
Key Derivation:
  Client ECDHE Private + Server ECDHE Public = Shared Secret
  Shared Secret → HKDF → Session Keys

Result:
  - Client write key (client → server encryption)
  - Server write key (server → client encryption)
  - Forward secrecy: Compromise of server's long-term 
    private key doesn't decrypt past sessions

TLS 1.3 Handshake: 1 round trip (vs 2 in TLS 1.2)

Encryption at Rest

Recommended Algorithms

Use Case Recommended Avoid
Symmetric Encryption AES-256-GCM, ChaCha20-Poly1305 DES, 3DES, RC4, AES-ECB
Asymmetric Encryption RSA-2048+, ECDSA P-256+, Ed25519 RSA-1024, DSA
Key Exchange ECDHE (Curve25519, P-256) Static DH, RSA key exchange
Hashing SHA-256, SHA-384, SHA-3 MD5, SHA-1
Password Hashing Argon2id, bcrypt, scrypt MD5, SHA-1, plain SHA-256
TLS Version TLS 1.3, TLS 1.2 (with strong ciphers) TLS 1.0, TLS 1.1, SSL 3.0

Cloud Encryption Options

AWS S3 Encryption Options
# SSE-S3: AWS manages keys (simplest)
aws s3 cp file.txt s3://bucket/ --sse AES256

# SSE-KMS: You control key in AWS KMS
aws s3 cp file.txt s3://bucket/ --sse aws:kms --sse-kms-key-id alias/my-key

# SSE-C: You provide the key (AWS doesn't store it)
aws s3 cp file.txt s3://bucket/ --sse-c --sse-c-key fileb://my-key.bin

# Client-Side Encryption: Encrypt before upload
# AWS never sees plaintext or key

Encryption Best Practices

Encryption Implementation Guidelines

1. Encrypt Everything in Transit: TLS 1.2+ minimum, prefer TLS 1.3. No exceptions for internal traffic.

2. Encrypt Sensitive Data at Rest: PII, credentials, financial data. Use column-level for high-value fields.

3. Use Authenticated Encryption: AES-GCM, ChaCha20-Poly1305. Ensures integrity + confidentiality.

4. Never Roll Your Own Crypto: Use established libraries (OpenSSL, libsodium, AWS Encryption SDK).

5. Protect Your Keys: HSMs for highest security, KMS for cloud. Keys are more valuable than data.

6. Plan for Key Rotation: Design systems to support key rotation from day one. Re-encryption strategy.
