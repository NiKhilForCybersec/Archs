VPN Security

Virtual Private Networks (VPNs) create encrypted tunnels for secure remote access. While VPNs remain important, modern Zero Trust architectures are reducing reliance on network-level access in favor of application-level security.

VPN Types

IPSec VPN
  • Network layer (Layer 3)
  • Site-to-site or client-to-site
  • Native OS support (IKEv2)
  • Requires client software or config
  • Strong encryption (AES-256)
  • Full network access typically

Use for: Site-to-site connectivity, traditional remote access, network-level VPN

SSL/TLS VPN
  • Application layer (Layer 7)
  • Clientless (browser) or client
  • Works through firewalls (port 443)
  • Granular application access
  • Easier deployment
  • Portal-based access common

Use for: Remote workers, BYOD, granular app access, easier deployment

VPN Architecture

Split Tunneling

Full Tunnel (All Traffic)
  • All traffic goes through VPN
  • Maximum visibility and control
  • Higher latency for cloud apps
  • More bandwidth on VPN gateway
  • Hairpin to SaaS apps (M365, etc.)

Use when: Maximum security required, need to inspect all traffic, compliance requirements

Split Tunnel (Selective)
  • Only corporate traffic through VPN
  • Direct access to cloud apps
  • Better performance
  • Less VPN gateway load
  • Requires endpoint security

Use when: Heavy cloud app usage, performance critical, strong endpoint controls in place

VPN vs ZTNA

Capability Traditional VPN ZTNA
Access Model Network-level access Application-level access
Trust Model Trust after authentication Never trust, always verify
Lateral Movement Full network access possible Limited to authorized apps
User Experience Connect/disconnect VPN Seamless, always-on
Visibility Network traffic Application activity
Infrastructure On-prem gateway Cloud-delivered
Modern Approach

Many organizations are moving from VPN to ZTNA for user access, keeping VPN only for site-to-site connectivity and legacy applications that require network-level access. ZTNA provides better security posture with least-privilege access.

VPN Security Best Practices

VPN Implementation Guidelines

1. Require MFA: VPN without MFA is single point of failure. Stolen credentials = full network access.

2. Use Strong Encryption: AES-256 for symmetric, RSA-2048+ or ECDSA for asymmetric. Disable weak ciphers.

3. Patch VPN Appliances: VPN vulnerabilities are prime targets. Patch within 24-48 hours of critical CVEs.

4. Consider ZTNA: For user access, ZTNA provides better security model. VPN for site-to-site and legacy only.

5. Monitor VPN Sessions: Log all connections. Alert on unusual patterns, geographic anomalies, off-hours access.

6. Integrate with NAC: Check device posture before granting access. No VPN access for non-compliant devices.
