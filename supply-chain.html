Supply Chain Security

Software supply chain attacks compromise trusted components, build systems, or distribution channels. SolarWinds, Codecov, and dependency confusion attacks demonstrate the devastating impact of supply chain compromises.

Supply Chain Attack Vectors

Compromised Dependencies

Malicious packages in npm, PyPI. Typosquatting, dependency confusion. You install attacker's code.

Build System Compromise

SolarWinds-style attack. Legitimate build process produces backdoored software. Most dangerous.

Compromised Updates

Malware delivered via auto-update mechanism. Users trust updates implicitly.

Third-Party Services

Codecov attack. CI/CD tool exfiltrates secrets. Trusted integration becomes attacker.

SLSA Framework

Supply Chain Levels for Software Artifacts
# SLSA (Supply-chain Levels for Software Artifacts)

SLSA LEVEL 1: Documentation
┌────────────────────────────────────────────────────┐
│ • Build process documented                         │
│ • Provenance generated (who, what, when)          │
│ • Basic auditability                               │
└────────────────────────────────────────────────────┘

SLSA LEVEL 2: Build Service
┌────────────────────────────────────────────────────┐
│ • Hosted build service (not local)                │
│ • Authenticated provenance                         │
│ • Version control for source                       │
└────────────────────────────────────────────────────┘

SLSA LEVEL 3: Build Platform Security
┌────────────────────────────────────────────────────┐
│ • Hardened build platform                          │
│ • Non-falsifiable provenance                       │
│ • Isolated builds                                  │
│ • Verified source integrity                        │
└────────────────────────────────────────────────────┘

SLSA LEVEL 4: Two-Person Review
┌────────────────────────────────────────────────────┐
│ • Two-party review of all changes                 │
│ • Hermetic builds                                  │
│ • Reproducible builds                              │
│ • Strongest supply chain guarantee                 │
└────────────────────────────────────────────────────┘

Supply Chain Controls

Control What It Addresses Implementation
Dependency Scanning Vulnerable/malicious packages Snyk, Dependabot, Socket.dev
Artifact Signing Tampering, authenticity Sigstore, GPG, Code signing
Private Registries Dependency confusion Artifactory, Nexus, internal npm
SBOM Component visibility CycloneDX, SPDX generation
Build Isolation Build compromise Ephemeral builders, hermetic builds
Lockfiles Unexpected dependency changes package-lock.json, requirements.txt pins

Supply Chain Best Practices

Supply Chain Security Guidelines

1. Verify Everything: Check signatures, hashes, provenance. Trust but verify.

2. Pin Dependencies: Lockfiles prevent surprise updates. Review dependency changes.

3. Use Private Registries: Proxy public packages through private registry. Blocks dependency confusion.

4. Scan Continuously: New vulnerabilities emerge. Continuous SCA, not just at build time.

5. Secure Build Pipeline: Harden CI/CD. Least privilege. Audit access to build systems.

6. Generate SBOMs: Know what's in your software. Required for government contracts.
