Penetration Testing

Penetration testing simulates real-world attacks to identify exploitable vulnerabilities. Unlike vulnerability scanning, pen testing validates that vulnerabilities can actually be exploited and chains them to demonstrate business impact.

Penetration Test Types

Type Knowledge Level Scope Best For
Black Box No prior knowledge External perspective Realistic external attacker simulation
White Box Full knowledge (code, architecture) Deep analysis Thorough security assessment
Gray Box Partial knowledge (credentials, docs) Balanced approach Efficient testing with context
External Internet-facing assets Perimeter Web apps, VPN, email
Internal Inside network Assume breach Lateral movement, privilege escalation
Social Engineering Human targets People/process Phishing, physical access

                            │

   ┌────────────────────────────────────────────────────┐
   │ • Passive: OSINT, DNS, social media, job postings │

Pen Test vs Vulnerability Scan vs Red Team

Vulnerability Scan

Automated tool identifies known vulnerabilities. No exploitation. Broad coverage, many false positives. Run frequently (weekly/monthly).

Penetration Test

Human-driven exploitation of vulnerabilities. Validates real risk. Scoped, time-limited. Annual or after major changes.

Red Team

Adversary simulation with objectives (steal data, access CEO email). Tests detection and response. Longer duration, full TTPs.

Penetration Testing Best Practices

Penetration Testing Guidelines

1. Get Written Authorization: Always have signed permission before testing. Protect yourself and the tester.

2. Define Clear Scope: In-scope systems, out-of-scope (production DBs?), testing windows, emergency contacts.

3. Test Regularly: Annual minimum. After major changes, new applications, or significant infrastructure updates.

4. Remediate and Retest: Findings without fixes are wasted effort. Verify remediation with retest.

5. Use Qualified Testers: OSCP, GPEN, CREST certifications indicate competence.

6. Include Internal Tests: External-only misses insider threat and assume-breach scenarios.
