Digital Forensics

Digital forensics is the scientific process of collecting, preserving, analyzing, and presenting digital evidence. Proper forensic procedures ensure evidence integrity for incident response, legal proceedings, and root cause analysis.

Forensic Process

Order of Volatility

Collect Most Volatile First!

1. CPU Registers & Cache - Gone in nanoseconds

2. Memory (RAM) - Lost on power off or reboot

3. Network State - Connections, routing tables

4. Running Processes - Process list, handles

5. Disk - Persistent but can be overwritten

6. Remote Logs - SIEM, cloud logs (most stable)

Evidence Collection

Linux Forensic Collection
# Memory Acquisition (do this FIRST)
# Using LiME (Linux Memory Extractor)
insmod lime.ko "path=/evidence/memory.lime format=lime"

# Or using AVML (Microsoft)
./avml /evidence/memory.raw

# Disk Imaging (after memory)
# Create forensic image with hash
dc3dd if=/dev/sda of=/evidence/disk.dd hash=sha256 \
  hashlog=/evidence/disk.dd.sha256

# Or using FTK Imager CLI
ftkimager /dev/sda /evidence/disk.E01 --e01

# Verify hash
sha256sum /evidence/disk.dd

# Collect volatile data before shutdown
date > /evidence/volatile/timestamp.txt
ps auxf > /evidence/volatile/processes.txt
netstat -an > /evidence/volatile/netstat.txt
lsof -n > /evidence/volatile/openfiles.txt
cat /proc/*/maps > /evidence/volatile/memory_maps.txt
last > /evidence/volatile/logins.txt
history > /evidence/volatile/history.txt

# Windows: Use KAPE, Velociraptor, or commercial tools

  Location: Building A, Desk 42
  Collected By: John Smith (Security Analyst)

  1. Photographed device and surroundings

  5. Sealed evidence bag with tamper seal #TS-98765

  Memory Image: SHA256: 3a7bd3e2f...
  Disk Image:   SHA256: 9c8f7a6b5...

Transfer Log:
  2024-12-06 15:00: John Smith → Evidence Locker (Rm 101)
  2024-12-07 09:00: Evidence Locker → Sarah Chen (Forensic Analyst)
  2024-12-10 16:00: Sarah Chen → Legal Hold Storage

All transfers witnessed and signed.
Evidence integrity verified via hash comparison at each transfer.

Key Forensic Artifacts

Artifact Location (Windows) Evidence Value
Event Logs C:\Windows\System32\winevt\Logs\ Logins, process execution, security events
Prefetch C:\Windows\Prefetch\ Program execution history, timestamps
Registry C:\Windows\System32\config\ User activity, installed software, USB history
Browser History %APPDATA%\Local\Google\Chrome\ Web activity, downloads, searches
$MFT NTFS Master File Table All files including deleted, timestamps
Amcache C:\Windows\appcompat\Programs\ Application execution, SHA1 hashes

Forensics Best Practices

Digital Forensics Guidelines

1. Memory First: Always capture RAM before disk. Memory contains running processes, network connections, encryption keys.

2. Work on Copies: Never analyze original evidence. Create forensic images, verify with hashes.

3. Document Everything: Every action, every finding. Chain of custody must be unbroken.

4. Use Write Blockers: Prevent accidental modification when imaging drives.

5. Timeline Everything: Super timelines correlate events across all artifact sources.

6. Prepare in Advance: Have forensic toolkit ready. When incidents happen, time is critical.
