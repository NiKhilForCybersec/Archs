File Integrity Monitoring (FIM)

File Integrity Monitoring detects unauthorized changes to critical system files, configurations, and data. FIM is essential for detecting malware persistence, insider threats, and is required by PCI-DSS, HIPAA, and other compliance frameworks.

How FIM Works

FIM Process Flow
# File Integrity Monitoring Process

1. BASELINE CREATION
   ┌────────────────────────────────────────────────────┐
   │ • Calculate hash (SHA-256) of monitored files     │
   │ • Record permissions, ownership, timestamps       │
   │ • Store baseline in secure database               │
   └────────────────────────────────────────────────────┘
                            │
                            ▼
2. CONTINUOUS MONITORING
   ┌────────────────────────────────────────────────────┐
   │ • Real-time: Hook file system events (inotify)    │
   │ • Scheduled: Periodic hash recalculation          │
   │ • Compare current state vs baseline               │
   └────────────────────────────────────────────────────┘
                            │
                            ▼
3. CHANGE DETECTION
   ┌────────────────────────────────────────────────────┐
   │ File: /etc/passwd                                 │
   │ Change Type: Content Modified                     │
   │ Old Hash: a1b2c3d4...                            │
   │ New Hash: e5f6g7h8...                            │
   │ Changed By: root (PID 1234)                      │
   │ Timestamp: 2024-12-06 14:32:15 UTC               │
   └────────────────────────────────────────────────────┘
                            │
                            ▼
4. ALERT & RESPONSE
   ┌────────────────────────────────────────────────────┐
   │ • Alert to SIEM                                   │
   │ • Create incident ticket                          │
   │ • Automated response (optional)                   │
   │ • Update baseline if approved change              │
   └────────────────────────────────────────────────────┘

What to Monitor

Category Examples (Linux) Examples (Windows)
System Binaries /bin, /sbin, /usr/bin C:\Windows\System32
Configuration Files /etc/passwd, /etc/shadow, /etc/ssh/sshd_config Registry keys, GPO files
Boot Files /boot/grub, /boot/vmlinuz BCD, bootloader
Application Configs nginx.conf, httpd.conf IIS config, web.config
Startup Scripts /etc/init.d, /etc/cron.d Startup folder, scheduled tasks
Sensitive Data Database files, key files Certificates, encryption keys

FIM Compliance Requirements

Regulatory FIM Requirements

PCI-DSS 11.5: Deploy FIM to alert on unauthorized modification of critical system files, configuration files, or content files. Compare at least weekly.

HIPAA §164.312(b): Implement mechanisms to record and examine activity in systems containing ePHI.

SOX Section 404: Controls to ensure integrity of financial data and systems.

NIST 800-53 SI-7: Employ integrity verification tools to detect unauthorized changes.

FIM Best Practices

FIM Implementation Guidelines

1. Start Focused: Monitor critical files first. Too broad = alert fatigue. Expand gradually.

2. Baseline After Patching: Update baselines after approved changes (patches, configs).

3. Real-Time for Critical: Use real-time monitoring for security-critical files. Scheduled for others.

4. Integrate with SIEM: FIM alerts need context. Correlate with other security events.

5. Exclude Noise: Log files, temp files, cache directories create noise. Exclude appropriately.

6. Change Management Integration: Link FIM to change tickets. Expected vs unexpected changes.
