Active Directory Security

Active Directory is the keys to the kingdom for most enterprises. Compromising AD means compromising everything. Modern AD security requires tiered administration, credential protection, attack surface reduction, and continuous monitoring for identity-based attacks.

Common AD Attack Techniques

Kerberoasting

Request service tickets for SPNs, crack offline to get service account passwords. Works against any user with an SPN.

MITRE: T1558.003

Pass-the-Hash

Use NTLM hash directly for authentication without knowing password. Extracted from memory (Mimikatz) or SAM.

MITRE: T1550.002

DCSync

Impersonate DC to request password hashes via replication. Requires Replicating Directory Changes permission.

MITRE: T1003.006

Golden Ticket

Forge Kerberos TGT with KRBTGT hash. Unlimited persistence—survives password resets except KRBTGT.

MITRE: T1558.001

Tiered Administration Model

Critical Rule

Domain Admins should NEVER log into workstations or member servers. If a DA logs into a compromised workstation, their credentials are exposed in memory → attackers extract with Mimikatz → game over.

Privileged Access Workstations (PAWs)

Traditional Admin Access
  • Admin logs into their regular workstation
  • Uses same machine for email, browsing, admin
  • RDPs to servers from daily-use workstation
  • Credentials cached on potentially compromised host
  • Phishing email → workstation compromised → DA creds stolen
PAW Model
  • Dedicated hardened workstation for admin tasks only
  • No email, no browsing, no general productivity
  • Admin tasks ONLY from PAW
  • Separate physical or VM-isolated machine
  • Even if daily workstation compromised, PAW is clean

Detecting AD Attacks

KQL - Kerberoasting Detection
// Detect potential Kerberoasting - mass TGS requests for SPNs
SecurityEvent
| where EventID == 4769  // Kerberos Service Ticket Operation
| where ServiceName !endswith "$"  // Exclude machine accounts
| where TicketEncryptionType in ("0x17", "0x18")  // RC4 encryption (weak, crackable)
| summarize 
    SPNCount = dcount(ServiceName),
    SPNs = make_set(ServiceName),
    RequestCount = count()
    by AccountName, ClientAddress, bin(TimeGenerated, 5m)
| where SPNCount > 10  // More than 10 unique SPNs in 5 minutes
| project TimeGenerated, AccountName, ClientAddress, SPNCount, SPNs

// Why this works:
// Normal users request 1-2 service tickets occasionally
// Kerberoasting requests tickets for MANY SPNs to crack offline
KQL - DCSync Detection
// Detect DCSync attack - non-DC requesting directory replication
SecurityEvent
| where EventID == 4662  // Operation performed on object
| where ObjectType contains "domainDNS"
| where Properties contains "Replicating Directory Changes"
| where SubjectUserName !endswith "$"  // Not a machine account
| where SubjectUserName !in ("MSOL_*", "AAD_*")  // Exclude legit sync accounts
| project TimeGenerated, SubjectUserName, SubjectDomainName, 
          ObjectName, Properties, IpAddress

// Why this works:
// Only Domain Controllers should request replication
// Non-DC accounts with this permission = compromise or misconfiguration

AD Hardening Checklist

Critical AD Security Controls

1. KRBTGT Password Reset: Reset twice (with replication between), every 180 days minimum. Invalidates Golden Tickets.

2. Protected Users Group: Add privileged accounts. Prevents NTLM auth, credential caching, delegation.

3. LAPS (Local Admin Password Solution): Unique, rotating local admin passwords per machine. Prevents lateral movement via shared local admin.

4. Credential Guard: Virtualization-based security isolates LSASS. Prevents Mimikatz-style credential theft.

5. Disable NTLM Where Possible: Audit NTLM usage, migrate to Kerberos. NTLM hashes are easily passed.

6. gMSA for Service Accounts: Group Managed Service Accounts have 240-char passwords, auto-rotate. Eliminates Kerberoasting risk.
