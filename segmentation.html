Network Segmentation

Network segmentation divides a network into isolated zones to limit lateral movement, contain breaches, and enforce the principle of least privilege at the network layer. Properly implemented segmentation means a compromised workstation can't directly reach your database servers.

Why Segmentation Matters

Flat Network (No Segmentation)
  • All devices on same subnet (10.0.0.0/8)
  • Workstations can reach servers directly
  • Printers can talk to databases
  • IoT devices on corporate network
  • No east-west traffic inspection
  • Single compromise = full network access

Attack Path: Phishing email → compromised workstation → network scan → find DC → credential theft → domain admin → access everything

Segmented Network
  • Separate zones for different asset types
  • Firewall between every zone
  • Users can only reach authorized resources
  • IoT/OT on isolated networks
  • East-west traffic logged and inspected
  • Compromise contained to segment

Attack Contained: Phishing → compromised workstation → can't reach servers (blocked by firewall) → attacker stuck in user segment → detection triggers

Common Network Zones

Segmentation Implementation

Method How It Works Pros Cons
VLANs Layer 2 separation at switch level Simple, widely supported, no extra hardware No inspection between VLANs without L3
Firewall Zones Routing between segments through NGFW Full L7 inspection, logging, policy Firewall becomes bottleneck, complex rules
SDN/Overlay Software-defined network fabric Flexible, policy-driven, scalable Complexity, vendor lock-in
Micro-Segmentation Host-based firewalls with central policy Granular (per-workload), works in cloud Agent required, complex policy mgmt
Air Gap Complete physical separation Maximum isolation Operational overhead, data transfer challenges

Segmentation Best Practices

Implementation Guidelines

1. Start with Asset Classification: You can't segment what you don't understand. Inventory assets, classify by sensitivity, identify data flows.

2. Protect Crown Jewels First: Segment your most critical assets (DC, databases, PAM) before broader segmentation.

3. Default Deny Between Zones: Block all traffic between zones by default. Explicitly allow only required flows.

4. Log All Inter-Zone Traffic: Every packet crossing a zone boundary should be logged for visibility and forensics.

5. Separate Management Plane: Dedicated management network for infrastructure access (out-of-band management).

6. Isolate IoT/OT: IoT devices on separate network with minimal outbound access. They should never reach corporate resources.
