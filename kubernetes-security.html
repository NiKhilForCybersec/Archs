Kubernetes Security

Kubernetes introduces unique security challenges: multi-tenant clusters, dynamic workloads, east-west traffic, and a complex API surface. Securing K8s requires defense in depth across the cluster, nodes, network, and workloads.

Kubernetes Security Layers

RBAC Configuration

Kubernetes RBAC Example
# Role: What permissions are granted
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: production
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
- apiGroups: [""]
  resources: ["pods/exec"]
  verbs: []  # Explicitly deny exec!

---
# RoleBinding: Who gets the permissions
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: production
subjects:
- kind: ServiceAccount
  name: monitoring-sa
  namespace: production
- kind: Group
  name: developers
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io

# RBAC Best Practices:
# ✓ Use Roles (namespace-scoped), not ClusterRoles when possible
# ✓ Never grant cluster-admin to applications
# ✓ Avoid wildcards (*) in resources and verbs
# ✓ Audit RBAC regularly with tools like rbac-lookup
# ✓ Use dedicated ServiceAccounts per application

Pod Security Standards

Profile Description Restrictions
Privileged Unrestricted (default) None - allows everything
Baseline Minimally restrictive No privileged, hostNetwork, hostPID. Blocks known escalations.
Restricted Heavily restricted Run as non-root, drop capabilities, read-only root FS, seccomp
Enforce Restricted Pod Security
# Apply restricted profile to namespace
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted

---
# Compliant pod specification
apiVersion: v1
kind: Pod
metadata:
  name: secure-app
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 1000
    fsGroup: 1000
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: app
    image: myapp:v1.2.3
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
          - ALL
    resources:
      limits:
        memory: "256Mi"
        cpu: "500m"
      requests:
        memory: "128Mi"
        cpu: "250m"

Network Policies

Default Deny with Selective Allow
Network Policy Examples
# 1. Default deny all ingress in namespace
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: production
spec:
  podSelector: {}  # Applies to all pods
  policyTypes:
  - Ingress
  # No ingress rules = deny all

---
# 2. Allow traffic only from frontend to backend
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-allow-frontend
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend
    ports:
    - protocol: TCP
      port: 8080

---
# 3. Allow backend to database only
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: database-allow-backend
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: database
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: backend
    ports:
    - protocol: TCP
      port: 5432

# Result: frontend → backend (8080) → database (5432)
#         frontend → database: BLOCKED
#         Any other pod → anything: BLOCKED

Image Security

Image Scanning

Scan images for CVEs before deployment. Block images with critical vulnerabilities. Trivy, Grype, Clair, Snyk.

Image Signing

Cryptographically sign images. Verify signatures before pulling. Cosign, Notary, Sigstore.

Private Registry

Pull only from trusted registries. Block public Docker Hub pulls. Use admission control.

Base Image Hardening

Minimal base images (distroless, Alpine). No shells, package managers. Reduce attack surface.

Kubernetes Security Best Practices

Kubernetes Security Implementation Guidelines

1. Enable Pod Security Standards: Enforce "restricted" profile. Start with "warn" mode, then move to "enforce".

2. Default Deny Network Policies: No pod should communicate without explicit policy. Zero trust inside the cluster.

3. Scan Images in CI/CD: Block deployments with critical CVEs. Integrate Trivy/Grype into pipeline.

4. Use RBAC Properly: Least privilege. No cluster-admin for apps. Dedicated ServiceAccounts per workload.

5. Enable Audit Logging: Log all API server requests. Ship to SIEM. Alert on suspicious activity.

6. Secrets via External Store: Don't use Kubernetes Secrets alone. Integrate Vault, AWS Secrets Manager with CSI driver.
