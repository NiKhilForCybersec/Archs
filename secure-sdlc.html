Secure Software Development Lifecycle (SSDLC)

Secure SDLC integrates security activities into every phase of software development—from requirements through deployment. Finding vulnerabilities early is dramatically cheaper than fixing them in production.

Threat Modeling

STRIDE Category Threat Type Example Mitigation
Spoofing Identity theft Fake user login Strong authentication, MFA
Tampering Data modification Modified API request Integrity checks, signing
Repudiation Denying actions User denies transaction Audit logging, non-repudiation
Info Disclosure Data exposure API returns too much data Encryption, access controls
Denial of Service Availability attack Resource exhaustion Rate limiting, scaling
Elevation of Privilege Gaining access User becomes admin Authorization, least privilege

Relative Cost to Fix by Phase

Requirements: 1x (baseline cost)

Design: 5x

Development: 10x

Testing: 20x

Production: 30-100x

Source: IBM Systems Sciences Institute, NIST

Secure SDLC Best Practices

Secure SDLC Guidelines

1. Threat Model Early: Identify threats during design. Architecture changes are cheap; code changes are expensive.

2. Security Champions: Embed security-minded developers in each team. Scale security expertise.

3. Automate Security Testing: SAST, SCA, secret scanning in CI/CD. Make security part of the pipeline.

4. Train Developers: Secure coding training is foundational. Developers write more code than security reviews.

5. Define Security Gates: Clear criteria for each phase. No deployment with critical vulnerabilities.

6. Measure and Improve: Track vulnerability density, mean time to fix. Improve continuously.
