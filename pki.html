PKI & Certificates

Public Key Infrastructure (PKI) provides the trust foundation for secure communications. Certificates enable TLS encryption, code signing, email security, and device authentication across the enterprise.

Certificate Hierarchy

Two-Tier PKI Architecture
# Enterprise PKI Hierarchy

                    ┌─────────────────────┐
                    │     Root CA         │
                    │  (Offline, HSM)     │
                    │  Validity: 20 years │
                    └──────────┬──────────┘
                               │
           ┌───────────────────┼───────────────────┐
           │                   │                   │
           ▼                   ▼                   ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│  Issuing CA 1    │ │  Issuing CA 2    │ │  Issuing CA 3    │
│  (Web/TLS)       │ │  (Code Signing)  │ │  (User/Device)   │
│  Validity: 10yr  │ │  Validity: 10yr  │ │  Validity: 10yr  │
└────────┬─────────┘ └────────┬─────────┘ └────────┬─────────┘
         │                    │                    │
         ▼                    ▼                    ▼
   End-Entity Certs    Code Sign Certs      User/Device Certs
   (1-2 years)         (3 years)            (1 year)

Key Design Principles:
  • Root CA offline (air-gapped), only used to sign subordinate CAs
  • Issuing CAs online, handle day-to-day certificate issuance
  • Separate CAs for different certificate types (security isolation)
  • Root CA private key in HSM, never exported
  • CRL/OCSP for revocation checking

ACME & Automation

Let's Encrypt with Certbot
# ACME Protocol - Automatic Certificate Management

# Install certbot
apt install certbot python3-certbot-nginx

# Obtain certificate (HTTP-01 challenge)
certbot certonly --nginx -d webapp.company.com

# Certificates stored in:
# /etc/letsencrypt/live/webapp.company.com/
#   ├── cert.pem      (server certificate)
#   ├── chain.pem     (intermediate CA)
#   ├── fullchain.pem (cert + chain)
#   └── privkey.pem   (private key)

# Auto-renewal (runs twice daily via systemd timer)
certbot renew --dry-run

# For internal services, use internal ACME CA:
# - Step CA (smallstep)
# - HashiCorp Vault PKI
# - ADCS with ACME support (Windows Server 2022+)

Benefits of ACME:
  • Automated issuance and renewal
  • No manual CSR generation
  • Certificates renewed before expiration
  • Eliminates certificate expiration outages

PKI Best Practices

PKI Implementation Guidelines

1. Protect Root CA: Offline, air-gapped, HSM-backed. Only brought online to sign subordinate CAs.

2. Automate Certificate Management: Use ACME for public certs. Certificate lifecycle management tool for visibility.

3. Monitor Expiration: Alert 90/60/30 days before expiration. Certificate outages are preventable.

4. Use Short Validity: 1 year max for TLS. Shorter = less exposure if compromised. Automation enables this.

5. Implement Certificate Transparency: Monitor CT logs for unauthorized certificates for your domains.

6. Have Revocation Plan: Test CRL/OCSP. Know how to revoke certificates quickly if compromised.
