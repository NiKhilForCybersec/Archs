Threat Intelligence

Cyber Threat Intelligence (CTI) is evidence-based knowledge about threats that enables informed decisions. It transforms raw data about adversaries into actionable insights that improve detection, accelerate response, and inform security strategy.

The Pyramid of Pain

Pyramid of Pain

The Pyramid of Pain (David Bianco) illustrates how much "pain" different indicator types cause attackers when detected and blocked. Hash values at the bottom are trivial to evade (recompile = new hash). TTPs at the top require the attacker to fundamentally change their tradecraft.

Key insight: Focus detection on TTPs and behaviors, not just IOCs. Behavioral detections force attackers to change how they operate, not just what tools they use.

Types of Threat Intelligence

Type Audience Content Example
Strategic Executives, Board High-level trends, risk landscape, business impact "Ransomware targeting manufacturing increased 47% in Q3"
Tactical SOC Analysts, IR TTPs, attack patterns, MITRE mappings "APT29 uses DLL side-loading via Teams updater (T1574.002)"
Operational IR Teams, Threat Hunters Specific campaigns, actor attribution, timing "FIN7 campaign targeting retail POS systems active Dec 2024"
Technical Security Tools, Automation IOCs: hashes, IPs, domains, file paths "C2: 185.234.72[.]19, Hash: a1b2c3d4..."

Operationalizing Threat Intel

From Intel Report to Detection Rule
1
Receive Threat Intelligence Report
Commercial feed reports new APT29 campaign
Intel Report
Source: Mandiant Threat Intel
Date: 2024-01-15
Title: APT29 Targeting Financial Services with Novel Loader

Summary:
APT29 (Cozy Bear) observed using new loader dubbed
"QUARTERRIG" delivered via spear-phishing. Loader uses
DLL search order hijacking with legitimate Microsoft
Teams updater.

TTPs:
- T1566.001: Spear-phishing with attachment
- T1574.001: DLL Search Order Hijacking  
- T1059.001: PowerShell execution
- T1071.001: HTTPS C2

IOCs:
- teamsupdate[.]services (C2 domain)
- 185.234.72[.]19 (C2 IP)
- a7b3c1d4e5f6... (QUARTERRIG SHA256)
2
Assess Relevance
Does this apply to our organization?
Relevance Assessment
Relevance Checklist:
  ✓ Industry: Financial Services (we are a bank)
  ✓ Geography: North America (we operate here)
  ✓ Technology: Microsoft Teams (we use it)
  ✓ Attack Vector: Email (primary entry point)
  
Verdict: HIGHLY RELEVANT - Prioritize immediately

Risk Assessment:
  Likelihood: HIGH (active campaign, targeting our sector)
  Impact: CRITICAL (APT29 = nation-state, data theft)
  Priority: P1 - Immediate action required
3
Create Detections
Build detection rules for both IOCs and TTPs
Detection Rules
// IOC-based detection (quick but fragile)
let C2_Domains = dynamic(["teamsupdate.services"]);
let C2_IPs = dynamic(["185.234.72.19"]);

DnsEvents
| where Name has_any (C2_Domains)
| project TimeGenerated, Computer, Name

NetworkEvents  
| where RemoteIP in (C2_IPs)
| project TimeGenerated, DeviceName, RemoteIP

// TTP-based detection (robust, survives IOC rotation)
// Detect DLL hijacking via Teams updater path
DeviceProcessEvents
| where FolderPath endswith "\\Microsoft\\Teams\\current\\squirrel.exe"
| where ProcessCommandLine has "update"
| join kind=inner (
    DeviceImageLoadEvents
    | where FolderPath !startswith "C:\\Program Files"
    | where FileName endswith ".dll"
) on DeviceId, Timestamp
| project TimeGenerated, DeviceName, ProcessCommandLine, LoadedDLL=FileName
4
Deploy & Monitor
Push IOCs to blocking controls, deploy detection rules
Deployment
Blocking Actions:
  ✓ Firewall: Block 185.234.72.19 (outbound)
  ✓ DNS: Sinkhole teamsupdate.services
  ✓ Email Gateway: Block attachment hash
  ✓ EDR: Add hash to blocklist

Detection Deployment:
  ✓ SIEM: Deploy KQL detection rules
  ✓ EDR: Custom IOC watchlist created
  ✓ Proxy: SSL inspection for C2 domain patterns

Validation:
  ✓ Test detection fires on simulated activity
  ✓ Confirm blocks working (test connection)
  ✓ Brief SOC on new detection context

Monitoring:
  - Dashboard created for APT29 indicators
  - Scheduled hunt for historical matches
  - 30-day retention on IOCs before review

Threat Intel Best Practices

Threat Intelligence Success Factors

1. Focus on TTPs Over IOCs: IOCs have short shelf lives. TTP-based detections survive attacker infrastructure changes.

2. Relevance Filtering: Not all intel is relevant to you. Filter by industry, geography, and technology stack before acting.

3. Automate IOC Ingestion: Use TIP platforms (MISP, ThreatConnect) to automatically push IOCs to security tools.

4. Measure Effectiveness: Track: How many alerts came from intel? How many were true positives? Did we detect before damage?

5. Share Back: Participate in ISACs and sharing communities. Intel is a two-way street.

6. Age Out Old IOCs: IOCs decay. Review and remove old indicators that generate noise without value.
