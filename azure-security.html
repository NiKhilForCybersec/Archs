Azure Security

Azure provides a comprehensive set of native security services spanning identity, network, compute, data, and operations. Understanding these services and how they integrate is essential for building secure cloud architectures.

Azure Security Services Landscape

Network Security Groups (NSGs)

NSG Traffic Flow: Web App Architecture
1
Internet User Request
User connects to web application via Azure Load Balancer
Inbound Request
Source: Internet (any)
Destination: Azure Load Balancer Public IP
Port: 443 (HTTPS)

Load Balancer forwards to backend pool:
  → Web tier VMs in web-subnet (10.0.1.0/24)
2
Web Tier NSG Evaluation
NSG attached to web-subnet processes rules
NSG: web-tier-nsg
Inbound Rules (evaluated in priority order):

Priority | Name              | Source      | Dest    | Port | Action
---------|-------------------|-------------|---------|------|--------
100      | Allow-LB-Health   | AzureLB     | Any     | Any  | Allow
110      | Allow-HTTPS-In    | Internet    | Any     | 443  | Allow
120      | Allow-HTTP-In     | Internet    | Any     | 80   | Allow
200      | Allow-Mgmt-SSH    | 10.0.0.0/24 | Any     | 22   | Allow
65000    | AllowVnetInBound  | VirtualNet  | VNet    | Any  | Allow
65500    | DenyAllInBound    | Any         | Any     | Any  | DENY

Result: HTTPS from Internet → ALLOWED (rule 110)
3
Web to App Tier Communication
Web server calls API on app tier
NSG: app-tier-nsg
Web Server: GET http://10.0.2.10:8080/api/data

App Tier NSG Inbound Rules:

Priority | Name              | Source        | Dest | Port | Action
---------|-------------------|---------------|------|------|--------
100      | Allow-Web-to-App  | 10.0.1.0/24   | Any  | 8080 | Allow
200      | Allow-Mgmt-SSH    | 10.0.0.0/24   | Any  | 22   | Allow
65500    | DenyAllInBound    | Any           | Any  | Any  | DENY

Result: Web subnet (10.0.1.0/24) → App on 8080 → ALLOWED

⚠️ Note: Direct Internet → App tier is BLOCKED
         Only web tier can reach app tier
4
App to Database Tier
App server queries Azure SQL Database
Database Access
App Server: SELECT * FROM customers

Azure SQL Database Security:
  1. Private Endpoint in data-subnet (10.0.3.0/24)
  2. NSG on data-subnet:
  
Priority | Name              | Source        | Dest | Port | Action
---------|-------------------|---------------|------|------|--------
100      | Allow-App-to-SQL  | 10.0.2.0/24   | Any  | 1433 | Allow
65500    | DenyAllInBound    | Any           | Any  | Any  | DENY

  3. SQL Firewall: Allow VNet only
  4. No public endpoint (disabled)

Result: Multi-layer protection
  - NSG: Only app tier on 1433
  - Private Endpoint: No internet exposure
  - SQL Firewall: Deny all public

Azure Key Vault

App Retrieving Secret from Key Vault (Managed Identity)
1
App Service Requests Secret
Application needs database connection string
Application Code
// C# - Using Managed Identity (no credentials in code!)
var client = new SecretClient(
    new Uri("https://contoso-kv.vault.azure.net/"),
    new DefaultAzureCredential()  // Uses managed identity
);

KeyVaultSecret secret = await client.GetSecretAsync("db-connection-string");
2
Managed Identity Authentication
Azure authenticates the app's identity automatically
Authentication Flow
App Service Managed Identity:
  Identity Type: System-assigned
  Object ID: a1b2c3d4-e5f6-7890-abcd-ef1234567890
  
Azure AD Authentication:
  1. App calls Azure Instance Metadata Service (IMDS)
  2. IMDS returns token for the managed identity
  3. Token scoped to Key Vault resource
  
No secrets, passwords, or certificates stored in app!
3
Key Vault Access Policy Check
Key Vault validates the identity has permission
Access Control
Key Vault: contoso-kv
Access Model: Azure RBAC (recommended)

Role Assignment:
  Principal: contoso-app-service (managed identity)
  Role: Key Vault Secrets User
  Scope: /subscriptions/.../resourceGroups/.../providers/
         Microsoft.KeyVault/vaults/contoso-kv

Evaluation:
  ✓ Identity authenticated (valid token)
  ✓ Role assigned (Secrets User)
  ✓ Secret exists (db-connection-string)
  
Result: Secret value returned to application

Audit Log:
  Operation: SecretGet
  Caller: contoso-app-service
  Secret: db-connection-string
  Result: Success

Azure Security Best Practices

Azure Security Implementation Guidelines

1. Use Managed Identities: Never store credentials in code or config. Managed identities provide automatic, secure authentication.

2. Enable Defender for Cloud: At minimum enable free tier. For production workloads, enable Defender plans for servers, containers, and databases.

3. NSGs on Every Subnet: Default deny all. Explicitly allow only required traffic. Use Application Security Groups for dynamic membership.

4. Private Endpoints for PaaS: Disable public endpoints on Azure SQL, Storage, Key Vault. Use Private Link for secure access.

5. Azure Policy for Guardrails: Enforce security requirements at scale: require encryption, deny public IPs, require specific SKUs.

6. Centralize Logs in Sentinel: Send all diagnostic logs, NSG flow logs, and activity logs to Log Analytics for threat detection.
