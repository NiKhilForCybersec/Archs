Network Detection & Response (NDR)

NDR monitors network traffic to detect threats that bypass endpoint security. Using machine learning and behavioral analytics, NDR identifies lateral movement, command and control, data exfiltration, and other malicious activity by analyzing network metadata and packets.

IDS vs. NDR

Traditional IDS/IPS
  • Signature-based detection
  • Matches known attack patterns
  • Point-in-time analysis
  • High volume of alerts, many false positives
  • Cannot detect novel attacks
  • Limited visibility into encrypted traffic

Limitation: Attacker uses custom malware → no matching signature → attack proceeds undetected.

Network Detection & Response
  • Behavioral + ML-based detection
  • Learns normal, alerts on anomalies
  • Historical analysis and correlation
  • Prioritized, high-fidelity alerts
  • Detects unknown threats via behavior
  • Encrypted traffic analysis (JA3/JA4, metadata)

Benefit: Custom malware → unusual beaconing pattern → NDR detects anomaly → alert with full network context.

Encrypted Traffic Analysis

Seeing Through Encryption

90%+ of network traffic is encrypted. NDR doesn't decrypt—instead it analyzes metadata:

JA3/JA4 Fingerprinting: TLS handshake creates unique fingerprint. Known malware has known JA3 hashes.

Certificate Analysis: Self-signed certs, unusual issuers, cert age, subject anomalies.

Connection Metadata: Timing, packet sizes, frequency patterns reveal behavior without decryption.

DNS Correlation: What domains were resolved before this encrypted connection?

NDR Best Practices

NDR Implementation Guidelines

1. Cover Critical Segments: At minimum: internet egress, data center core, cloud VPCs. Prioritize where crown jewels live.

2. Baseline Before Alerting: Let NDR learn normal behavior for 2-4 weeks before tuning alerts. Reduces false positives significantly.

3. Integrate with EDR/SIEM: NDR + EDR = complete picture. Network sees what endpoints miss, and vice versa.

4. Retain PCAP for Forensics: When incident happens, you'll want packet-level evidence. Plan storage accordingly.

5. Monitor East-West: Most attacks move laterally. Internal network visibility is as important as perimeter.

6. Include Cloud Traffic: VPC flow logs, cloud-native NDR sensors. Cloud workloads need same visibility.
