Zero Trust Network Access (ZTNA)

ZTNA provides secure, identity-based access to specific applications rather than entire network segments. It implements the "never trust, always verify" principle by authenticating users and validating device health before granting least-privilege access to individual applications.

VPN vs. ZTNA

Traditional VPN
  • Network-level access (full LAN connectivity)
  • Connect once → access everything
  • Implicit trust after authentication
  • Visible network perimeter (VPN gateway IP)
  • Complex split-tunneling decisions
  • Lateral movement possible after compromise
  • Hair-pinning traffic through datacenter
  • Limited device posture checking
1
User connects to VPN
IPsec/SSL tunnel to VPN gateway
2
Full network access granted
User can reach ALL internal resources (10.0.0.0/8)
3
Attacker pivots laterally
Compromised laptop → scans internal network → finds DC
Zero Trust Network Access
  • Application-level access (specific apps only)
  • Authenticate per-application
  • Continuous verification (re-evaluate risk)
  • Dark cloud (apps invisible to internet)
  • No network-level access needed
  • Lateral movement prevented by design
  • Direct-to-app (cloud-delivered)
  • Deep device posture assessment
1
User requests specific app
SAP ERP via ZTNA connector
2
Identity + device verified
MFA + compliant device + user risk = low
3
Access ONLY to SAP
No network access, can't see/reach other systems

ZTNA Architecture

Key Architecture Concepts

Dark Cloud: Applications are not exposed to the internet. No public IPs, no open firewall ports. Attackers can't scan/discover them.

Inside-Out Connectivity: Connectors make outbound connections to the ZTNA cloud. No inbound firewall rules required.

Micro-Tunnels: Each user-to-app session is a separate encrypted tunnel. No lateral movement between apps.

ZTNA Implementation Best Practices

Success Factors

1. Start with High-Value Apps: Begin with crown jewel applications (ERP, HR systems, admin consoles). Don't try to migrate everything at once.

2. Define Device Posture Baseline: Determine minimum security requirements (encryption, AV, patch level) before deployment. Be prepared to handle exceptions.

3. Integrate with Existing IdP: Leverage your existing identity provider (Entra, Okta, Ping) for consistent MFA and SSO experience.

4. Deploy Connectors Redundantly: At least 2 connectors per application segment for high availability. Place connectors close to applications.

5. Plan for Hybrid: Most organizations will run ZTNA alongside VPN during transition. Plan coexistence strategy.

6. Monitor and Optimize: Track latency, user experience, and policy hits. Optimize connector placement and policy specificity over time.
