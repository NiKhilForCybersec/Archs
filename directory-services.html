Directory Services

Directory services are the foundation of enterprise identity. Active Directory and Entra ID store user identities, group memberships, and authentication data. Compromising directory services means compromising everything—making their security absolutely critical.

Directory Services Landscape

Common Directory Attacks

Kerberoasting

Request service tickets for SPNs, crack offline. Targets service accounts with weak passwords. Any domain user can perform this attack.

DCSync

Impersonate DC to replicate password hashes. Requires Replicating Directory Changes. Often achieved via compromised admin account.

Golden Ticket

Forge Kerberos TGT using KRBTGT hash. Provides domain-wide access. Persists until KRBTGT password reset twice.

Pass-the-Hash

Authenticate using NTLM hash without knowing password. Common lateral movement technique. Enabled by credential caching.

AD Tiered Administration Model

Why Tiering Matters

Without tiering: Attacker compromises workstation → steals cached Domain Admin credentials → instant domain compromise.

With tiering: Attacker compromises workstation → finds only Tier 2 credentials → cannot escalate to servers or DCs → attack contained.

AD Hardening Checklist

Critical AD Security Controls
# TIER 0 PROTECTION
□ Dedicated Tier 0 admin accounts (never used on workstations)
□ Privileged Access Workstations (PAWs) for DC administration
□ Domain Admin accounts in Protected Users group
□ KRBTGT password rotated twice annually
□ Domain Controllers on dedicated network segment
□ Defender for Identity monitoring all DCs

# KERBEROS HARDENING
□ Disable RC4 encryption (force AES)
□ Service accounts use gMSA (25+ char auto-rotating passwords)
□ Enable Kerberos armoring (FAST)
□ Audit Kerberos ticket requests (Event ID 4769)

# CREDENTIAL PROTECTION  
□ Credential Guard enabled on all systems
□ LAPS deployed for local admin passwords
□ Disable NTLM where possible (audit first)
□ Block credential delegation (CredSSP restrictions)

# MONITORING & DETECTION
□ Monitor sensitive groups (Domain Admins, Schema Admins)
□ Alert on DCSync (Replicating Directory Changes)
□ Detect Kerberoasting (mass TGS requests)
□ Monitor AdminSDHolder modifications

# PowerShell: Add users to Protected Users
Add-ADGroupMember -Identity "Protected Users" -Members "admin-jsmith"

# Protected Users restrictions:
# - No NTLM authentication
# - No DES or RC4 in Kerberos
# - No credential delegation
# - TGT lifetime reduced to 4 hours

Directory Security Best Practices

Directory Services Security Guidelines

1. Implement Tiered Administration: Tier 0/1/2 separation. Admin credentials for servers should never touch workstations.

2. Deploy Defender for Identity: Real-time monitoring for AD attacks—Kerberoasting, DCSync, lateral movement, reconnaissance.

3. Use Protected Users Group: Domain Admins, service accounts in Protected Users. Eliminates NTLM, forces Kerberos.

4. gMSA for Service Accounts: Eliminate static service account passwords. 240-character auto-rotating passwords.

5. Secure Entra Connect: This server can sync password hashes. Treat as Tier 0. Isolated, monitored, restricted.

6. Regular KRBTGT Rotation: Rotate KRBTGT password twice per year. Invalidates Golden Tickets.
