Container Security

Containers introduce new attack surfaces across the build, deploy, and runtime phases. Container security encompasses image scanning, registry security, runtime protection, Kubernetes hardening, and supply chain integrity to secure modern cloud-native applications.

Container Security Lifecycle

Image Vulnerability Scanning

CI/CD Pipeline Image Scan
# GitHub Actions - Scan image before push to registry
name: Container Security
on: [push]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Build image
        run: docker build -t myapp:${{ github.sha }} .
      
      - name: Scan for vulnerabilities
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: 'myapp:${{ github.sha }}'
          format: 'sarif'
          severity: 'CRITICAL,HIGH'
          exit-code: '1'  # Fail build on CRITICAL/HIGH
          
      - name: Sign image (if scan passes)
        run: |
          cosign sign --key cosign.key myapp:${{ github.sha }}
          
      - name: Push to registry (only signed images)
        run: |
          docker push registry.company.com/myapp:${{ github.sha }}

Kubernetes Security Controls

Pod Security Standards - Restricted
apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    runAsNonRoot: true           # Never run as root
    runAsUser: 1000              # Specific non-root user
    fsGroup: 1000                # File system group
    seccompProfile:
      type: RuntimeDefault       # Enable seccomp filtering
      
  containers:
  - name: app
    image: registry.company.com/myapp:v1.2.3@sha256:abc...  # Pin by digest
    securityContext:
      allowPrivilegeEscalation: false   # Block privilege escalation
      readOnlyRootFilesystem: true      # Immutable container filesystem
      capabilities:
        drop:
          - ALL                         # Drop all Linux capabilities
    resources:
      limits:
        memory: "256Mi"
        cpu: "500m"
      requests:
        memory: "128Mi"
        cpu: "250m"
    volumeMounts:
    - name: tmp
      mountPath: /tmp
      
  volumes:
  - name: tmp
    emptyDir: {}                        # Writable temp directory only
Network Policy - Default Deny
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: production
spec:
  podSelector: {}          # Apply to all pods in namespace
  policyTypes:
  - Ingress
  - Egress
  # No ingress/egress rules = deny all traffic by default

---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-backend
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend    # Only frontend pods can reach backend
    ports:
    - protocol: TCP
      port: 8080

Container Security Best Practices

Container Security Implementation Guidelines

1. Use Minimal Base Images: Distroless, Alpine, or scratch. Fewer packages = smaller attack surface.

2. Never Run as Root: Always specify non-root USER in Dockerfile. Enable runAsNonRoot in K8s.

3. Scan in CI/CD: Block builds with CRITICAL vulnerabilities. Shift security left.

4. Sign and Verify Images: Use Cosign/Notary. Only deploy signed images from trusted registries.

5. Network Policies: Default deny, explicit allow. Micro-segment at the pod level.

6. Runtime Protection: Behavioral monitoring catches what static scanning misses. Detect anomalies in production.
