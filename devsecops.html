DevSecOps

DevSecOps integrates security into every phase of the software development lifecycle. By shifting security left—addressing vulnerabilities in design and code rather than production—organizations reduce risk, accelerate delivery, and build security into their DNA.

Secure CI/CD Pipeline

Security Testing Tools

Type What It Does When Tools
SAST Analyzes source code for vulnerabilities Build time SonarQube, Checkmarx, Semgrep
SCA Scans dependencies for known CVEs Build time Snyk, Dependabot, OWASP DC
DAST Tests running application for vulnerabilities Test/Staging OWASP ZAP, Burp Suite, Nuclei
Container Scan Scans container images for CVEs Release Trivy, Grype, Clair
IaC Scan Checks infrastructure code for misconfigs Deploy Checkov, tfsec, KICS
Secret Scan Finds hardcoded secrets in code/config Commit GitLeaks, TruffleHog, detect-secrets

Pipeline Security Configuration

GitHub Actions Security Pipeline
name: Security Pipeline
on: [push, pull_request]

jobs:
  security-scan:
    runs-on: ubuntu-latest
    steps:
      # Secret scanning (pre-commit should catch, this is backup)
      - name: GitLeaks Scan
        uses: gitleaks/gitleaks-action@v2
        
      # SAST - Static code analysis
      - name: SonarQube Scan
        uses: sonarsource/sonarqube-scan-action@master
        with:
          args: >
            -Dsonar.qualitygate.wait=true
            
      # SCA - Dependency vulnerabilities
      - name: Snyk Dependency Scan
        uses: snyk/actions/node@master
        with:
          args: --severity-threshold=high
          
      # Container image scanning
      - name: Build Image
        run: docker build -t myapp:${{ github.sha }} .
        
      - name: Trivy Container Scan
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: myapp:${{ github.sha }}
          severity: CRITICAL,HIGH
          exit-code: 1  # Fail pipeline on findings
          
      # IaC scanning (if Terraform/CloudFormation)
      - name: Checkov IaC Scan
        uses: bridgecrewio/checkov-action@master
        with:
          directory: ./infrastructure
          soft_fail: false

  # DAST runs against deployed staging environment
  dast-scan:
    needs: deploy-staging
    runs-on: ubuntu-latest
    steps:
      - name: OWASP ZAP Scan
        uses: zaproxy/[email protected]
        with:
          target: 'https://staging.myapp.com'
          rules_file_name: '.zap/rules.tsv'

DevSecOps Best Practices

DevSecOps Implementation Guidelines

1. Automate Everything: Security scans in every pipeline. No manual gates that can be bypassed. Make secure the easy path.

2. Fail Fast: Secret scanning in pre-commit hooks. SAST before code review. Find issues before they're merged.

3. Define Quality Gates: Clear thresholds for critical/high findings. Block deployments that don't meet standards.

4. Developer-Friendly Findings: Integrate into IDE, PR comments. Provide fix guidance. Don't just dump scan reports.

5. Track Metrics: Mean time to remediate. Vulnerability escape rate. Security debt over time.

6. Security Champions: Embedded security advocates in dev teams. First line of defense, not bottleneck.
