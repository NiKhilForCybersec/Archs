Endpoint Detection & Response (EDR)

EDR solutions provide continuous monitoring and response capabilities for endpoints, collecting detailed telemetry about process execution, network connections, file modifications, and more to detect and respond to threats that bypass traditional prevention controls.

What is EDR?

Endpoint Detection and Response (EDR) is a category of security tools that continuously monitors endpoints to detect, investigate, and respond to cyber threats. Unlike traditional antivirus that focuses on prevention through signatures, EDR assumes that some threats will bypass preventive controls and focuses on detection, investigation, and response capabilities.

Key Concept

EDR operates on the principle of "assume breach" — rather than trying only to prevent all attacks, it focuses on detecting attacks that get through and enabling rapid response to contain damage.

Traditional AV vs. Modern EDR

Traditional Approach (The Problem)

Signature-Based Antivirus

  • Relies on known malware signatures
  • Daily signature updates from vendor
  • On-access and scheduled file scanning
  • Simple alert: "Malware detected" or "Malware blocked"
  • No visibility into process behavior
  • No forensic data collection
  • Manual investigation required

Detection Flow

1
File Downloaded
User downloads malware.exe from email attachment
2
Signature Check
AV calculates hash, compares against signature database
3
Zero-Day Miss
New malware variant — hash not in database — ALLOWED TO RUN
4
Malware Executes
No behavioral monitoring — malicious actions proceed undetected
Modern Approach (The Solution)

EDR with Behavioral Analysis

  • Continuous telemetry collection from all endpoints
  • Behavioral analysis and machine learning
  • Process trees, command lines, network connections
  • Rich context: who, what, when, where, how
  • Automated response capabilities
  • Full forensic timeline
  • MITRE ATT&CK mapping

Detection Flow

1
File Downloaded
User downloads malware.exe — sensor records file write
2
Process Execution Monitored
cmd.exe → powershell.exe -enc [base64] recorded with full command line
3
Behavioral Detection
ML model flags: encoded PowerShell + network beacon + registry persistence
4
Automated Response
Process killed, host isolated, alert with full context sent to SOC

Risks Without EDR

Critical Vulnerabilities

Zero-Day Attacks: New malware variants with no existing signatures bypass traditional AV entirely. Studies show 60-70% of malware is zero-day at time of attack.

Fileless Malware: Attacks living entirely in memory (PowerShell, WMI, .NET) leave no files for AV to scan. Traditional AV is blind to these techniques.

Living-off-the-Land: Attackers using legitimate system tools (certutil, mshta, regsvr32) aren't flagged because the binaries are trusted.

No Forensic Data: When a breach occurs, there's no telemetry to understand what happened, how, or what was accessed.

Slow Response: Manual investigation can take days or weeks, allowing attackers to maintain persistence and exfiltrate data.

1

Execution — Macro Spawns PowerShell
VBA macro executes encoded PowerShell command. This is a highly suspicious behavior: Office application spawning PowerShell.
Telemetry Captured

  ParentProcess: WINWORD.EXE  ← Office spawning shell = SUSPICIOUS
  Process: powershell.exe
  CommandLine: powershell.exe -nop -w hidden -enc JABjAGwAaQBlAG4AdAA...
  IntegrityLevel: Medium
  
Detection Trigger: 
  Rule: "Suspicious Process Spawn from Office Application"
  MITRE: T1059.001 (PowerShell)
  Severity: HIGH
3
Command & Control — Network Beacon
PowerShell establishes connection to C2 server. EDR captures network connection with full context.
Telemetry Captured

  Process: powershell.exe (PID: 4532)
  RemoteIP: 185.234.72.19
  RemotePort: 443
  Protocol: TCP/TLS
  Domain: cdn-static[.]net  ← Not in Alexa top 1M
  
Threat Intel Match:
  IP 185.234.72.19 → Known Cobalt Strike C2
  Confidence: 95%
  
Detection Trigger:
  Rule: "Connection to Known C2 Infrastructure"
  MITRE: T1071.001 (Web Protocols)
  Severity: CRITICAL
4
Persistence — Registry Run Key
Malware establishes persistence via registry. Traditional AV would not see this as the binary is legitimate PowerShell.
Telemetry Captured 
RegistryModification:
  Process: powershell.exe
  Key: HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  Value: "WindowsUpdate"
  Data: "powershell.exe -w hidden -enc JABjAGwAaQBlAG4AdAA..."
  
Detection Trigger:
  Rule: "Encoded PowerShell in Registry Persistence"
  MITRE: T1547.001 (Registry Run Keys)
  Severity: HIGH
5
Automated Response — Containment
EDR automatically contains the threat based on policy. Total time from execution to containment: 12 seconds.
Response Actions Taken 
AutomatedResponse:
  Action 1: Kill Process
    Target: powershell.exe (PID: 4532)
    Result: SUCCESS
    
  Action 2: Network Isolation
    Target: WORKSTATION-PC01
    Result: SUCCESS (only EDR cloud traffic allowed)
    
  Action 3: Remove Persistence
    Target: HKCU\...\Run\WindowsUpdate
    Result: SUCCESS
    
  Action 4: Alert SOC
    Severity: CRITICAL
    Incident ID: INC-2024-0115-001
    
Timeline:
  14:32:15 - Document opened
  14:32:18 - PowerShell spawned
  14:32:19 - C2 connection detected
  14:32:27 - Automated containment complete
  
Total Response Time: 12 seconds

Key Telemetry Types

Telemetry Type Data Collected Detection Use Cases
Process Events Process name, PID, parent process, command line, user, timestamps, hashes Suspicious process chains, LOLBins abuse, encoded commands
File Events File path, operation (create/modify/delete), hash, entropy Ransomware behavior, malware drops, data staging
Network Events Source/dest IP, ports, protocol, DNS queries, bytes transferred C2 communication, lateral movement, data exfiltration
Registry Events Key path, value name, data, operation type Persistence mechanisms, defense evasion, configuration changes
Authentication Events Logon type, source, account, success/failure Credential theft, lateral movement, brute force
Module/DLL Loads Module path, hash, loading process DLL injection, sideloading, reflective loading

MITRE ATT&CK Coverage

Modern EDR solutions map detections to the MITRE ATT&CK framework, providing standardized language for describing adversary behaviors.

Pro Tip

When evaluating EDR solutions, request their MITRE ATT&CK coverage matrix. Focus on techniques relevant to your threat model rather than total coverage percentage.

Implementation Best Practices

Deployment Recommendations

1. Coverage First: Deploy to 100% of endpoints before fine-tuning. Gaps in coverage are the biggest risk.

2. Start in Detect Mode: Run prevention policies in detect-only mode initially to baseline normal behavior and reduce false positives.

3. Integrate with SIEM: Forward all detections to your SIEM for correlation with other security data sources.

4. Enable Automated Response Gradually: Start with low-risk automated actions (alerts, process termination) before enabling network isolation.

5. Develop Response Playbooks: Create documented procedures for common detection types before incidents occur.

6. Threat Hunting Program: Use EDR telemetry proactively to hunt for threats, not just react to alerts.
