Compliance Frameworks

Security compliance frameworks provide structured approaches to protecting data and systems. Whether regulatory (PCI-DSS, HIPAA) or voluntary (SOC 2, ISO 27001), these frameworks establish security baselines and demonstrate due diligence to customers and regulators.

Framework Overview

Framework Scope Required For Certification
PCI-DSS Payment card data protection Anyone processing credit cards Annual assessment (QSA/SAQ)
HIPAA Protected health information Healthcare, business associates No formal certification (audits)
SOC 2 Service organization controls SaaS, cloud providers (customer request) Type I or Type II report
ISO 27001 Information security management Voluntary (enterprise standard) 3-year certification + annual audits
NIST CSF Cybersecurity framework US federal contractors, voluntary Self-assessment
GDPR Personal data protection EU data subjects No certification (regulatory)

SOC 2 Trust Service Criteria

Security (Required)

Protection against unauthorized access. Firewalls, access controls, MFA, encryption, monitoring. Foundation for all SOC 2 reports.

Availability

System is available for operation as committed. SLAs, redundancy, disaster recovery, incident response.

Processing Integrity

System processing is complete, accurate, timely. Quality assurance, error handling, audit trails.

Confidentiality

Information designated as confidential is protected. Encryption, access controls, data classification.

Privacy

Personal information collected, used, retained, disclosed per privacy notice. GDPR-like requirements.

SOC 2 Type I vs Type II

Type I: Point-in-time assessment. Controls are designed appropriately. Faster, cheaper, but limited value.

Type II: Period assessment (6-12 months). Controls operated effectively. More valuable, required by sophisticated customers.

Framework Mapping

Control Mapping Across Frameworks
# Example: Multi-Factor Authentication requirement

PCI-DSS 4.0:
  Requirement 8.4.2: MFA for all access into the CDE
  Requirement 8.4.3: MFA for all non-console admin access

SOC 2:
  CC6.1: Logical access security (MFA as control activity)

ISO 27001:
  A.9.4.2: Secure log-on procedures

NIST CSF:
  PR.AC-7: Users, devices, and other assets are authenticated

HIPAA:
  §164.312(d): Person or entity authentication

# Benefit of mapping:
# - Implement MFA once, satisfy 5+ frameworks
# - Reduces audit fatigue
# - Unified control documentation
# - GRC tools automate this mapping

Compliance Best Practices

Compliance Implementation Guidelines

1. Build Once, Comply Many: Map controls across frameworks. Implement strong controls that satisfy multiple requirements simultaneously.

2. Automate Evidence Collection: Use GRC platforms to continuously collect compliance evidence. No more audit fire drills.

3. Continuous Compliance: Don't treat compliance as annual event. Continuous monitoring, continuous improvement.

4. Security First, Compliance Second: Good security naturally achieves compliance. Checkbox compliance without security is theater.

5. Document Everything: Policies, procedures, evidence of execution. If it's not documented, it didn't happen.

6. Scope Carefully: Minimize compliance scope where possible (PCI CDE segmentation). Smaller scope = less cost.
