Secrets Management

Secrets—API keys, database passwords, certificates, tokens—are the keys to your kingdom. Hardcoded secrets in code, config files, and environment variables are a leading cause of breaches. Centralized secrets management with dynamic credentials is essential.

The Secrets Problem

Secrets Anti-Patterns
  • Hardcoded in source code
  • Stored in config files
  • Environment variables in plain text
  • Shared across applications
  • Never rotated
  • Committed to Git repositories

Risk: Developer commits AWS keys to public GitHub → automated scanners find it in seconds → crypto mining charges in minutes.

Secrets Best Practices
  • Centralized secrets vault
  • Dynamic, short-lived credentials
  • Encrypted at rest and in transit
  • Per-application, per-environment secrets
  • Automatic rotation
  • Full audit trail

Benefit: App requests DB credentials from Vault → receives unique credentials valid for 1 hour → auto-rotates → compromise limited to single app, single hour.

Secrets Management Architecture

Dynamic Secrets

HashiCorp Vault Dynamic Database Credentials
1
Configure Database Engine
One-time setup by admin
Vault Configuration
# Enable database secrets engine
vault secrets enable database

# Configure PostgreSQL connection
vault write database/config/prod-db \
  plugin_name=postgresql-database-plugin \
  connection_url="postgresql://{{username}}:{{password}}@db.company.com:5432/prod" \
  allowed_roles="app-readonly,app-readwrite" \
  username="vault-admin" \
  password="$ADMIN_PASSWORD"

# Create role with limited permissions
vault write database/roles/app-readonly \
  db_name=prod-db \
  creation_statements="CREATE ROLE \"{{name}}\" WITH LOGIN PASSWORD '{{password}}' VALID UNTIL '{{expiration}}'; GRANT SELECT ON ALL TABLES IN SCHEMA public TO \"{{name}}\";" \
  default_ttl="1h" \
  max_ttl="24h"
2
Application Requests Credentials
Get unique, short-lived credentials
Application Request
# App authenticates to Vault (using AppRole, K8s SA, etc.)
vault login -method=approle role_id=$ROLE_ID secret_id=$SECRET_ID

# Request database credentials
vault read database/creds/app-readonly

Key             Value
---             -----
lease_id        database/creds/app-readonly/abc123
lease_duration  1h
username        v-approle-app-readon-xyz789
password        A1B2C3D4-random-generated
3
Automatic Cleanup
Credentials expire and are revoked
Lifecycle
Timeline:
  T+0:    Credentials created (v-approle-app-readon-xyz789)
  T+50m:  App can renew lease (extend TTL)
  T+1h:   Lease expires
  T+1h:   Vault automatically runs:
          DROP ROLE "v-approle-app-readon-xyz789";

Benefits:
  ✓ Each request = unique credentials
  ✓ Credentials auto-expire
  ✓ Compromised cred limited to 1 hour
  ✓ Full audit trail of who requested what
  ✓ No long-lived passwords anywhere

Secrets Management Best Practices

Secrets Management Implementation Guidelines

1. Never Hardcode Secrets: Zero exceptions. Use pre-commit hooks and secret scanning to prevent accidents.

2. Use Dynamic Secrets: Short-lived, automatically rotated. Eliminate the "shared password that never changes" problem.

3. Least Privilege: Applications get only the secrets they need. Different environments get different secrets.

4. Audit Everything: Every secret access logged. Alert on unusual patterns. Required for compliance.

5. Secret Scanning: Scan repos, container images, config for leaked secrets. GitHub, GitLeaks, TruffleHog.

6. Rotate on Compromise: Automated rotation capability. If secret is exposed, rotate immediately—not in hours or days.
