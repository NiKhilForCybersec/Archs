Backup & Recovery

Backups are your last line of defense against ransomware and data loss. Modern backup strategies must account for sophisticated attackers who specifically target backup systems. Immutable backups, air-gapped storage, and regular testing are essential for true resilience.

Why Traditional Backups Fail Against Ransomware

Traditional Backup Approach
  • Backups on network-attached storage
  • Backup admin uses domain credentials
  • Same network as production systems
  • Backups can be modified or deleted
  • No verification of backup integrity
  • Restore rarely tested

Risk: Ransomware gains Domain Admin → enumerates backup systems → deletes/encrypts all backups → demands ransom with no recovery option.

Ransomware-Resilient Backup
  • Immutable backups (cannot be modified)
  • Isolated credentials (not domain-joined)
  • Air-gapped or isolated network
  • WORM storage / object lock
  • Integrity verification on every backup
  • Regular restore testing

Benefit: Ransomware gains DA → can't reach backup network → can't delete immutable backups → full recovery possible.

The 3-2-1-1-0 Rule

Immutable Backup Implementation

AWS S3 Object Lock (Immutable Backup)
# Create bucket with Object Lock enabled
aws s3api create-bucket \
  --bucket company-backups-immutable \
  --object-lock-enabled-for-bucket

# Set default retention (Compliance mode = even root can't delete)
aws s3api put-object-lock-configuration \
  --bucket company-backups-immutable \
  --object-lock-configuration '{
    "ObjectLockEnabled": "Enabled",
    "Rule": {
      "DefaultRetention": {
        "Mode": "COMPLIANCE",
        "Days": 30
      }
    }
  }'

# Upload backup with retention
aws s3api put-object \
  --bucket company-backups-immutable \
  --key backups/2024-01-15/full-backup.tar.gz \
  --body full-backup.tar.gz \
  --object-lock-mode COMPLIANCE \
  --object-lock-retain-until-date 2024-02-15T00:00:00Z

# Result: This backup CANNOT be deleted until Feb 15, 2024
# Even by: AWS root account, backup admins, ransomware
# Only time can release the lock
Immutability Options

AWS S3 Object Lock: Compliance mode (immutable) or Governance mode (admins can override)

Azure Immutable Blob: Time-based retention or legal hold policies

Veeam Hardened Repository: Linux with immutability flag, single-use credentials

Physical Air Gap: Tape in vault, disconnected systems—ultimate protection

Recovery Time Objectives

Metric Definition Example
RTO (Recovery Time Objective) Maximum acceptable downtime ERP system: 4 hours, Email: 1 hour
RPO (Recovery Point Objective) Maximum acceptable data loss Database: 15 minutes, File shares: 24 hours
MTTR (Mean Time to Recovery) Average actual recovery time Measured from incident to full restoration
Backup Strategy by RPO
RPO: Near-Zero (< 15 minutes)
  → Synchronous replication
  → Database transaction logs shipped continuously
  → Technologies: SQL Always On, Oracle Data Guard, Azure Site Recovery

RPO: 1-4 Hours
  → Hourly incremental backups
  → Application-aware snapshots
  → Technologies: Veeam, Commvault, storage snapshots

RPO: 24 Hours
  → Daily full/incremental backups
  → Acceptable for non-critical systems
  → Technologies: Traditional backup agents, file-level backup

Critical Question: If we restore from last night's backup,
what data do we lose? Is that acceptable for this system?

Backup Best Practices

Ransomware-Resilient Backup Guidelines

1. Immutable Backups Required: At least one backup copy must be immutable (Object Lock, WORM, air-gap). This is non-negotiable.

2. Separate Credentials: Backup admin accounts should NOT be domain-joined. Use dedicated, isolated authentication.

3. Network Isolation: Backup infrastructure on separate network segment. Zero trust between production and backup networks.

4. Test Recovery Regularly: Quarterly at minimum. Document and time the process. If you haven't tested it, assume it doesn't work.

5. Backup the Backup Config: Backup server itself, catalog, configurations. You need these to restore anything else.

6. Monitor Backup Jobs: Alert on failures immediately. Ransomware often disables backups days before encryption.
